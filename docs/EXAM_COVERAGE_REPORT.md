## Attempt-engine implications

- `/api/attempts/start` now ignores no client-controlled question count because the field has been removed. It selects the full current gradeable set, not an official-length blueprint.
- IDs are validated using a path-safe format that accepts seeded slugs as well as CUID-style IDs.
- `src/lib/exam/selection.ts` now fails before quota reservation when a gradeable Listening question lacks a matching `READY` audio-asset record, URL, and `verifiedAt`. This prevents a known no-audio prompt from silently entering a new attempt; it does **not** prove that the asset is reachable in deployment or plays in a browser.
- No per-exam expected section counts, item distributions, adaptive rules, task weights, or official score conversions are enforced in the attempt engine.

## Conclusion

The repository contains an exam catalog and legacy short-form sample scripts, not evidence of a complete bank. Do not publish “full mock,” “official-style score,” or exam-readiness claims until counts, content provenance, current blueprints, and end-to-end sessions are independently verified against an approved database and browser environment.

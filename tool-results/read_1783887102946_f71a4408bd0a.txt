     1→# ALO English Test Platform — Question Bank Guide
     2→
     3→**Audience:** Admins, exam managers, content authors, reviewers, ALO Practice Examiners.
     4→**Scope:** Authoring, reviewing, versioning, importing, exporting, and auditing the ALO question bank.
     5→**Compliance reminder:** Every item in the bank MUST be **100% original** content authored or licensed by ALO. No official exam items, no copyrighted third-party passages, no leaked material. See §4.
     6→
     7→---
     8→
     9→## 1. Question Bank Overview
    10→
    11→The ALO question bank is the single source of truth for every practice item on the platform. It powers:
    12→
    13→- the **universal CBT engine** (`app/Services/ExamEngine.php`);
    14→- the **practice-set assembly** workflow (`exam_practice_sets`, `exam_practice_set_sections`, `exam_practice_set_questions`);
    15→- the **weekly content pipeline** (`scripts/weekly_question_update.php`);
    16→- the **examiner review queue** for writing and speaking items (`exam_writing_submissions`, `exam_speaking_sessions`);
    17→- the **Smart Score Report** explanations (`exam_questions.explanation`).
    18→
    19→Tables involved (full schema in `database/install.sql`):
    20→
    21→| Table | Purpose |
    22→|---|---|
    23→| `exam_question_types` | The catalog of 58 supported response formats (see §3). |
    24→| `exam_questions` | The master question rows. One row per question. |
    25→| `exam_question_options` | Options for MCQ-type questions (correctness, sort order, optional feedback). |
    26→| `exam_question_media` | Linked media (passage text, image prompt, audio script, audio file URL, model answer). |
    27→| `exam_question_versions` | Snapshots of every published version of a question (see §7). |
    28→| `exam_question_review_queue` | Per-question review state (draft / in_review / approved / rejected / published). |
    29→| `exam_practice_set_questions` | Many-to-many link between a practice set's section and a question. |
    30→
    31→Each `exam_questions` row carries:
    32→
    33→- a unique `question_code` (e.g. `Q-IELTS-R-001`, `Q-SAT-M-003`, `Q-VISA-002`);
    34→- `exam_type_id` (1–32, foreign key into `exam_types`);
    35→- `section_id` (foreign key into `exam_sections`);
    36→- `question_type_id` (foreign key into `exam_question_types`);
    37→- `difficulty` (`easy`, `medium`, `hard`, `advanced`);
    38→- `tags` (comma-separated skill labels, see §5);
    39→- `prompt` (the question stem — Markdown supported);
    40→- `explanation` (teaches the concept; rendered in the Smart Score Report);
    41→- `time_seconds` (recommended seconds to answer);
    42→- `points` (default 1);
    43→- `is_active` (1 = live, 0 = retired);
    44→- `is_published` (1 = visible to students, 0 = draft or in review);
    45→- `created_by`, `reviewed_by`, `approved_by` (audit trail);
    46→- type-specific answer fields (see §3).

    50→## 2. How to Add a Question
    51→
    52→### 2.1 Via the Admin UI (recommended for hand-authored questions)
    53→
    54→1. **Log in** to `/admin` with an account that has the `questions.create` permission.
    55→2. Navigate to **Question Bank → New Question**.
    56→3. Pick the **exam type** (1–32). The section dropdown filters to that exam's sections.
    57→4. Pick the **section** (e.g. *Academic Reading*, *Verbal Reasoning*, *Credibility Interview*).
    58→5. Pick the **question type** (see §3). The form re-renders to show the type-specific answer fields.
    59→6. Fill in:
    60→   - `question_code` — auto-suggested based on exam + section + next sequence; editable but must be unique.
    61→   - `prompt` — Markdown supported. Long passages go in the **Passage** field (`exam_question_media.passage_text`) and are referenced from the prompt with `{{passage}}`.
    62→   - `difficulty` — easy / medium / hard / advanced.
    63→   - `tags` — multi-select from the tag catalog (§5). Custom tags require admin approval.
    64→   - `explanation` — Markdown; teach the concept, don't just restate the answer.
    65→   - `time_seconds` — recommended answer time.
    66→7. Fill the **type-specific answer fields** (see §3 for the full mapping).
    67→8. Attach **media** (optional): passage text, image prompt description, audio script, audio file URL, model answer.
    68→9. Save as **Draft**. The question enters `exam_question_review_queue` with `state = 'draft'`.
    69→10. (Author) Click **Submit for review**. The state moves to `in_review` and an ALO Practice Examiner is auto-assigned based on the exam type.
    70→
    71→### 2.2 Via CSV import
    72→
    73→Use the **Question Bank → Import → CSV** screen. Template (downloadable from the same screen):
    74→
    75→```csv
    76→question_code,exam_type,section,question_type,difficulty,tags,prompt,explanation,time_seconds,options,correct_index,correct_answer,model_answer,passage,audio_script
    77→Q-IELTS-R-099,IELTS-ACAD,ACAD_READING,single_mcq,medium,"academic-reading;inference","What is the writer's main claim about urban green spaces?","The passage frames green spaces as infrastructure, not decoration — see paragraph 2.",90,"They are essential urban infrastructure.|They are aesthetic luxuries.|They reduce property values.|They are difficult to maintain.",0,,,"Urban green spaces...",""
    78→```
    79→
    80→Rules:
    81→
    82→- Header row is required and must match the template exactly.
    83→- Use `|` to separate options inside the `options` cell.
    84→- `correct_index` is 0-based for MCQs; empty for non-MCQ.
    85→- `correct_answer` is used for `fill_blanks`, `short_answer`, `numeric_answer`, `write_from_dictation`.
    86→- `model_answer` is used for writing/speaking types.
    87→- `passage` and `audio_script` are stored in `exam_question_media` and linked to the question.
    88→- Empty optional fields are left blank (no `NULL` literal).
    89→- All rows enter `exam_question_review_queue` with `state = 'draft'`.
    90→
    91→### 2.3 Via JSON import
    92→
    93→Use the **Question Bank → Import → JSON** screen. The JSON schema mirrors the CSV columns plus optional nested `media` and `options` arrays:
    94→
    95→```json
    96→[
    97→  {
    98→    "question_code": "Q-IELTS-R-099",
    99→    "exam_type": "IELTS-ACAD",
   100→    "section": "ACAD_READING",
   101→    "question_type": "single_mcq",
   102→    "difficulty": "medium",
   103→    "tags": ["academic-reading", "inference"],
   104→    "prompt": "What is the writer's main claim about urban green spaces?",
   105→    "explanation": "The passage frames green spaces as infrastructure, not decoration — see paragraph 2.",
   106→    "time_seconds": 90,
   107→    "options": [
   108→      {"text": "They are essential urban infrastructure.", "is_correct": true},
   109→      {"text": "They are aesthetic luxuries.", "is_correct": false},
   110→      {"text": "They reduce property values.", "is_correct": false},
   111→      {"text": "They are difficult to maintain.", "is_correct": false}
   112→    ],
   113→    "media": {
   114→      "passage_text": "Urban green spaces..."
   115→    }
   116→  }
   117→]
   118→```
   119→
   120→JSON is preferred over CSV when:
   121→
   122→- options have per-option feedback (`feedback` field);
   123→- a question has multiple media attachments (passage + image prompt + audio script);
   124→- the import is generated by a script (the `gen_question_sets.py` generator emits SQL directly, but JSON is the supported import format for ad-hoc imports).
   125→
   126→### 2.4 Via the programmatic generator (for batch placeholders)
   127→
   128→`scripts/gen_question_sets.py` emits `database/question_sets_seed.sql` with 320 practice sets + sample original questions. Re-run only when the exam catalog changes; do NOT use it to author real content — its output is explicitly marked as `[Original placeholder prompt]`.

   132→## 3. The 58 Supported Question Types
   133→
   134→Stored in `exam_question_types`. Grouped here by response format and grading behavior. Each row has `is_graded_auto` (1 = auto-graded by `ScoringRules`, 0 = needs examiner/AI review).
   135→
   136→### 3.1 Objective — single-select MCQ (auto-graded)
   137→
   138→| `type_code` | `type_name` | Used by |
   139→|---|---|---|
   140→| `single_mcq` | Single Best Answer MCQ | All exams (default) |
   141→| `true_false_notgiven` | True / False / Not Given | IELTS Reading |
   142→| `yes_no_notgiven` | Yes / No / Not Given | IELTS Reading |
   143→| `central_idea` | Central Idea / Main Idea | SAT, ACT, GRE, LSAT, MCAT, all reading |
   144→| `inference` | Inference | TOEFL, SAT, LSAT, MCAT, all reading |
   145→| `vocabulary_in_context` | Vocabulary in Context | SAT, ACT, Placement |
   146→| `standard_english` | Standard English Conventions | SAT Writing |
   147→| `logical_reasoning` | Logical Reasoning | LSAT |
   148→| `analytical_reasoning` | Analytical Reasoning (Logic Games) | LSAT |
   149→| `critical_reasoning` | Critical Reasoning | GMAT |
   150→| `sentence_correction` | Sentence Correction | GMAT |
   151→| `problem_solving` | Problem Solving (Quant) | GMAT, SAT, ACT, GRE |
   152→| `data_interpretation` | Data Interpretation | GRE, GMAT, ACT Science, MCAT |
   153→
   154→**Answer fields:** `options` (array in `exam_question_options`), `correct_index` on the correct option row.
   155→
   156→### 3.2 Objective — multi-select MCQ (auto-graded)
   157→
   158→| `type_code` | `type_name` | Used by |
   159→|---|---|---|
   160→| `multi_mcq` | Multiple Correct MCQ | All exams |
   161→| `sentence_equivalence` | Sentence Equivalence | GRE |
   162→| `read_and_select` | Read and Select | Duolingo |
   163→
   164→**Answer fields:** `options` (array); `is_correct = 1` on every correct option. Partial credit is configurable per practice set (see `scoring_rule_json`).
   165→
   166→### 3.3 Objective — matching (auto-graded)
   167→
   168→| `type_code` | `type_name` | Used by |
   169→|---|---|---|
   170→| `matching_headings` | Matching Headings | IELTS Reading |
   171→| `matching_paragraphs` | Matching Information | IELTS Reading |
   172→| `matching_sentence_endings` | Matching Sentence Endings | IELTS Reading |
   173→| `matching_pairs` | Matching Pairs | All |
   174→
   175→**Answer fields:** `matching_pairs` JSON in `exam_question_media.matching_pairs` — `{"left": ["A","B","C"], "right": ["ii","iv","i"], "correct_mapping": {"A":"ii","B":"iv","C":"i"}}`.
   176→
   177→### 3.4 Objective — text / fill / cloze (auto-graded)
   178→
   179→| `type_code` | `type_name` | Used by |
   180→|---|---|---|
   181→| `sentence_completion` | Sentence Completion | IELTS Reading |
   182→| `summary_completion` | Summary Completion | IELTS Reading |
   183→| `fill_blanks` | Fill in the Blanks | All |
   184→| `short_answer` | Short Answer | IELTS, all |
   185→| `reading_fill_blanks` | Reading Fill in the Blanks (dropdown) | PTE |
   186→| `listening_fill_blanks` | Listening Fill in the Blanks | PTE |
   187→| `write_from_dictation` | Write From Dictation | PTE |
   188→| `interactive_reading` | Interactive Reading | Duolingo |
   189→| `complete_the_sentence` | Complete the Sentence (Cloze) | Duolingo |
   190→| `listen_and_type` | Listen and Type | Duolingo |
   191→
   192→**Answer fields:** `correct_answer` (string; for multi-blank, a `||`-separated list or a JSON object of `{blank_index: "answer"}`).
   193→
   194→### 3.5 Objective — numeric / quantitative (auto-graded)
   195→
   196→| `type_code` | `type_name` | Used by |
   197→|---|---|---|
   198→| `grid_in` | Numeric Grid-In | SAT |
   199→| `numeric_answer` | Numeric Answer (with tolerance) | All math |
   200→| `quantitative_comparison` | Quantitative Comparison | GRE |
   201→| `data_sufficiency` | Data Sufficiency | GMAT |
   202→
   203→**Answer fields:** `numeric_answer` for `grid_in` and `numeric_answer`; for `quantitative_comparison` the `options` array is fixed (`A: Quantity A is greater`, `B: Quantity B is greater`, `C: The two quantities are equal`, `D: The relationship cannot be determined`), and the question carries `quantity_a` + `quantity_b` text. For `data_sufficiency` the options are fixed A–E and the correct option is in `correct_index`.
   204→
   205→### 3.6 Objective — reorder / ordering (auto-graded)
   206→
   207→| `type_code` | `type_name` | Used by |
   208→|---|---|---|
   209→| `reorder_paragraphs` | Reorder Paragraphs | PTE |
   210→
   211→**Answer fields:** `reorder_items` (array) + `correct_order` (array of indexes).
   212→
   213→### 3.7 Writing — examiner/AI graded (`is_graded_auto = 0`)
   214→
   215→| `type_code` | `type_name` | Used by |
   216→|---|---|---|
   217→| `essay` | Essay | All exams |
   218→| `writing_task1` | Writing Task 1 (Academic — chart/diagram) | IELTS Academic |
   219→| `writing_task1_general` | Writing Task 1 (General — letter) | IELTS General |
   220→| `writing_task2` | Writing Task 2 | IELTS Academic/General, OIETC, Placement |
   221→| `integrated_writing` | Integrated Writing | TOEFL |
   222→| `academic_discussion` | Academic Discussion | TOEFL |
   223→| `writing_sample` | Writing Sample | Duolingo |
   224→| `issue_task` | Issue Task | GRE |
   225→| `argument_task` | Argument Task | GRE |
   226→| `summarize_spoken_text` | Summarize Spoken Text | PTE |
   227→| `summarize_written_text` | Summarize Written Text (one sentence) | PTE |
   228→
   229→**Answer fields:** `model_answer` (a high-scoring sample) in `exam_question_media`. Word-count limits enforced from `exam_settings.writing_word_count_min` / `writing_word_count_max` (default 150–750). Graded by `ScoringRules::rubric()` against the rubric in the practice set's `scoring_rule_json`.
   230→
   231→### 3.8 Speaking — examiner/AI graded (`is_graded_auto = 0`)
   232→
   233→| `type_code` | `type_name` | Used by |
   234→|---|---|---|
   235→| `read_aloud` | Read Aloud | PTE |
   236→| `repeat_sentence` | Repeat Sentence | PTE |
   237→| `describe_image` | Describe Image | PTE, Duolingo |
   238→| `retell_lecture` | Retell Lecture | PTE |
   239→| `speaking_part1` | Speaking Part 1 | IELTS, OIETC, LanguageCert, Placement |
   240→| `speaking_part2` | Speaking Part 2 (Cue Card) | IELTS, LanguageCert |
   241→| `speaking_part3` | Speaking Part 3 | IELTS, LanguageCert |
   242→| `independent_speaking` | Independent Speaking | TOEFL |
   243→| `speaking_sample` | Speaking Sample | Duolingo |
   244→| `credibility_interview` | Credibility Interview Prompt | Visa/Interview, ALO Internal |
   245→
   246→**Answer fields:** `model_answer` (a structured hint or 60-second sample transcript). Audio is uploaded by the CBT engine (`public/uploads/audio/`), master copy in `storage/private/audio/`. Graded by `Automated Practice Feedback` on 6 dimensions: fluency, pronunciation, lexical resource, grammar, coherence, task response.
   247→
   248→### 3.9 Adding a new question type
   249→
   250→1. Add a row to `exam_question_types` via `database/seed.sql` (or `database/migrations/<timestamp>_add_qtype_<code>.sql`).
   251→2. Extend the response renderer in `public/assets/js/exam-engine.js` (`AnswerRenderer` switch).
   252→3. Extend the scorer in `app/Services/ScoringRules.php` (`grade()` switch).
   253→4. Add an admin form section in `app/Views/admin/questions/_form_<type>.php`.
   254→5. Add a PHPUnit test case for the new type in `tests/Unit/ScoringRulesTest.php`.
   255→6. Update `docs/QUESTION_BANK_GUIDE.md` (this file) with the new type in §3.

   259→## 4. Originality Rules (non-negotiable)
   260→
   261→1. **No official exam items.** Every passage, audio script, prompt, distractor, model answer, chart, and image must be **100% original** content authored or licensed by ALO. Do not paraphrase, summarize, or "rephrase" official exam items — that is still a derivative work.
   262→2. **No copyrighted third-party content.** Do not copy passages from books, news articles, blogs, or other test-prep publishers. If you need a real-world source for a chart or data table, you must either (a) use a public-domain source and credit it, or (b) generate the data yourself and label it as illustrative.
   263→3. **No leaked material.** If a contributor reports that they have seen a question on a real exam, the question must NOT be added — even if reworded. Discard and document the report in `exam_audit_logs`.
   264→4. **No "real exam common questions" lists.** Do not curate lists of "commonly appearing" items. Every item must be standalone original practice.
   265→5. **No implication of official affiliation.** Wording on every question, explanation, and report MUST use the labels in §11 of `DEVELOPMENT-GUIDELINE.md` ("X-style practice test", "Original exam-aligned practice", "Not official exam content", "No guarantee of real-exam repetition").
   266→6. **Attribution.** If a passage draws on a real (public-domain or licensed) source, attribute it in the explanation. If a chart uses real public-domain data, attribute the source in the chart caption.
   267→7. **Source tracking.** Every question must have `source = 'original'` in `exam_questions.source` (default). If `source = 'licensed'`, the `license_url` and `license_note` fields must be populated.
   268→8. **Author identity.** `created_by` must point to a real user ID; anonymous authorship is forbidden.
   269→9. **Review must confirm originality.** The reviewer signs off on the `originality_confirmed` flag in `exam_question_review_queue` before forwarding to admin approval. The reviewer's ID is recorded.
   270→10. **Audit.** Every question's author, reviewer, approver, and edit history is preserved in `exam_audit_logs` and `exam_question_versions`. Any question found post-publish to violate originality rules is **immediately retired** (`is_active = 0`), removed from all published practice sets, and a post-mortem is opened.

   274→## 5. Difficulty Levels and Tags
   275→
   276→### 5.1 Difficulty
   277→
   278→`exam_questions.difficulty` is one of:
   279→
   280→| Level | Definition | Typical CEFR (for English) |
   281→|---|---|---|
   282→| `easy` | Foundational; tests recall and basic comprehension. | A2–B1 |
   283→| `medium` | Standard practice; tests application and analysis. | B1–B2 |
   284→| `hard` | Advanced; tests evaluation and inference. | B2–C1 |
   285→| `advanced` | Stretch; tests nuanced reasoning and synthesis. | C1–C2 |
   286→
   287→Every practice set rotates difficulty across its 10 sets (sets 1–10 cycle through easy/medium/hard/advanced by `(set_n - 1) % 4`) so that the published catalog always offers a difficulty gradient per exam.
   288→
   289→### 5.2 Tag catalog
   290→
   291→Tags live in `exam_questions.tags` (comma-separated). The canonical tag vocabulary:
   292→
   293→**Skill tags (English):**
   294→- `grammar`, `vocabulary`, `coherence`, `fluency`, `pronunciation`
   295→- `academic-reading`, `listening-detail`, `listening-gist`, `inference`, `main-idea`
   296→- `task-response`, `lexical-resource`, `grammatical-range`, `cohesion`
   297→
   298→**Skill tags (Quant):**
   299→- `algebra`, `geometry`, `arithmetic`, `statistics`, `data-analysis`, `probability`
   300→- `problem-solving`, `quant-comparison`, `data-sufficiency`
   301→
   302→**Skill tags (Interview/Visa):**
   303→- `credibility`, `study-plan`, `finances`, `career-plan`, `ties-to-home-country`
   304→
   305→**Cognitive tags (Bloom):**
   306→- `recall`, `comprehension`, `application`, `analysis`, `evaluation`, `synthesis`
   307→
   308→**Topic tags:** unlimited, but must be reviewed before publishing (e.g. `urban-green-spaces`, `coral-reefs`, `remote-work`, `sleep-science`).
   309→
   310→Custom tags require admin approval via the **Question Bank → Tags → Approve** screen. Approved tags appear in the tag multi-select on the question form.
   311→
   312→### 5.3 Tag-based practice
   313→
   314→Students can filter practice sets by tag (`/student/practice-tests?tag=inference`). The Student Dashboard → **Skill breakdown** chart aggregates scores by tag, so the student can see which skills need work.

   318→## 6. Review Workflow
   319→
   320→Every question moves through five states in `exam_question_review_queue`. The state machine is enforced by `QuestionBankService::transition()`.
   321→
   322→```
   323→   ┌─────────┐   submit for review    ┌──────────┐   approve          ┌──────────┐   publish    ┌───────────┐
   324→   │  draft  │ ─────────────────────▶ │ in_review│ ────────────────▶ │ approved │ ───────────▶ │ published │
   325→   └─────────┘                         └──────────┘                   └──────────┘              └───────────┘
   326→        ▲                                    │                              │                          │
   327→        │             reject                 │             reject           │                          │ retire
   328→        └────────────────────────────────────┴──────────────────────────────┘                          ▼
   329→                                                                                                                                 ┌──────────┐
   330→                                                                                                                                 │ retired  │
   331→                                                                                                                                 └──────────┘
   332→```
   333→
   334→### 6.1 Draft
   335→
   336→- Default state on creation (UI, CSV, JSON, or generator).
   337→- Visible only to the author and admins.
   338→- Author can edit any field.
   339→- Author cannot self-approve (RBAC: `questions.review` ≠ `questions.create`).
   340→
   341→### 6.2 In review
   342→
   343→- Author clicks **Submit for review**.
   344→- An ALO Practice Examiner is auto-assigned by `exam_type_id` (configured in `exam_settings.review_assignment_strategy`, default: round-robin among active examiners for that exam).
   345→- The reviewer sees the question in their **Review queue** at `/examiner`.
   346→- Reviewer actions:
   347→  - **Approve** → state moves to `approved`; `reviewed_by` is recorded; `originality_confirmed = 1`.
   348→  - **Reject** → state moves back to `draft`; reviewer adds a comment; author is notified by email.
   349→  - **Request changes** → state stays in `in_review`; reviewer adds a comment; author edits and resubmits.
   350→
   351→### 6.3 Approved
   352→
   353→- The reviewer has signed off; the question waits for an admin to publish.
   354→- An admin (with `questions.publish` permission) sees the question in **Question Bank → Pending publication**.
   355→- Admin can:
   356→  - **Publish** → state moves to `published`; `approved_by` is recorded; `is_published = 1`; a snapshot is written to `exam_question_versions` (see §7).
   357→  - **Reject** → state moves back to `in_review` (re-review required) with a comment.
   358→- By default (`exam_settings.auto_publish_after_approval = false`), auto-publish is **off**. The admin gate is intentional — it is the final compliance checkpoint.
   359→
   360→### 6.4 Published
   361→
   362→- The question is visible to students through practice sets that include it.
   363→- Any subsequent edit creates a new draft version (see §7); the published version is not changed until the new version is published.
   364→- A published question can be **retired** (`is_active = 0`); retired questions are excluded from new practice sets but remain visible in past attempts' reports.
   365→
   366→### 6.5 Retired
   367→
   368→- Retired questions stay in the bank for audit and historical report rendering, but cannot be added to new practice sets.
   369→- Retirement is reversible (admin only); on un-retire, the question returns to `published` state.
   370→
   371→### 6.6 SLA targets
   372→
   373→| Transition | Target SLA |
   374→|---|---|
   375→| Draft → In review | 1 business day (author responsibility) |
   376→| In review → Approved/Rejected | 2 business days (reviewer) |
   377→| Approved → Published | 1 business day (admin) |
   378→| Published → retired (compliance issue) | Within 4 hours of report |

   382→## 7. Versioning
   383→
   384→Every published version of a question is snapshotted in `exam_question_versions`:
   385→
   386→| Column | Purpose |
   387→|---|---|
   388→| `question_id` | FK to `exam_questions.id` |
   389→| `version` | 1, 2, 3, … |
   390→| `snapshot_json` | Full copy of the question row + options + media at the moment of publication |
   391→| `published_at` | When this version became live |
   392→| `published_by` | Admin user ID |
   393→| `superseded_at` | When a newer version was published (NULL = current) |
   394→
   395→When a published question is edited:
   396→
   397→1. The edit is made on a **new draft version** (the live row is not touched).
   398→2. The draft goes through the review workflow again.
   399→3. On publish, the current version's `superseded_at` is set, and a new `exam_question_versions` row is inserted.
   400→4. Past attempts continue to render against the version they were taken against (so the student's report never silently changes).
   401→5. The audit log records the diff between versions.
   402→
   403→This means:
   404→
   405→- A student who took a mock in January sees the January version in their report, even if the question was updated in March.
   406→- An admin can roll back to any previous version via **Question Bank → Versions → Roll back**.
   407→

   410→## 8. CSV / JSON Import
   411→
   412→### 8.1 CSV import
   413→
   414→- **Where:** Admin → Question Bank → Import → CSV.
   415→- **Required columns:** `question_code, exam_type, section, question_type, difficulty, tags, prompt, explanation, time_seconds`.
   416→- **Type-specific columns:** `options`, `correct_index`, `correct_answer`, `numeric_answer`, `quantity_a`, `quantity_b`, `reorder_items`, `correct_order`, `matching_pairs`, `model_answer`, `passage`, `audio_script`, `image_prompt`.
   417→- **Separator inside a cell:** `|` for arrays (options, tags); `||` for multi-blank answers; JSON object string for `matching_pairs`.
   418→- **Encoding:** UTF-8 with BOM.
   419→- **Max rows per import:** 500. Larger imports must be split.
   420→- **Pre-flight checks (run before any DB write):**
   421→  - header validation;
   422→  - `question_code` uniqueness (within the file AND against the DB);
   423→  - `exam_type` validity (must exist in `exam_types`);
   424→  - `section` validity (must exist in `exam_sections` for the given `exam_type`);
   425→  - `question_type` validity (must exist in `exam_question_types`);
   426→  - `difficulty` enum check;
   427→  - tag spelling check (warns on unknown tags; does not block);
   428→  - for MCQ types: `options` non-empty, `correct_index` in range;
   429→  - for `numeric_answer` / `grid_in`: `correct_answer` parses as a number;
   430→  - for `quantitative_comparison`: `quantity_a` and `quantity_b` both present;
   431→  - for `reorder_paragraphs`: `reorder_items` and `correct_order` arrays equal length;
   432→  - for writing/speaking types: `model_answer` non-empty.
   433→- **Failure behavior:** the import is atomic — if any row fails pre-flight, no rows are written. A downloadable error report lists every failing row and the reason.
   434→- **Post-import:** every imported row enters `exam_question_review_queue` with `state = 'draft'`. The author is set to the importing admin; the import batch ID is recorded in `exam_audit_logs` for traceability.
   435→
   436→### 8.2 JSON import
   437→
   438→- **Where:** Admin → Question Bank → Import → JSON.
   439→- **Schema:** see §2.3 for the example.
   440→- **Validation:** same as CSV, plus structural JSON validation (arrays, required keys, types).
   441→- **Nested fields supported:** `options[].feedback`, `media.image_prompt`, `media.audio_url`, `media.matching_pairs` (as a JSON object inside the JSON file).
   442→- **Bulk limit:** 500 questions per file.
   443→
   444→### 8.3 Export
   445→
   446→- Admin → Question Bank → Export → CSV or JSON.
   447→- Filters: by exam type, section, difficulty, tag, state (draft/in_review/approved/published/retired), author, date range.
   448→- Export respects RBAC: an examiner exporting their review queue gets only their assigned questions.
   449→- Exported files are written to `storage/private/exports/` and served via `DownloadController::serve()` with a 60-second signed URL.
   450→

   453→## 9. Quality Checks
   454→
   455→Before a question can be submitted for review, `QuestionBankService::qualityCheck()` runs the following. The check is also re-run on publish.
   456→
   457→### 9.1 Structural checks
   458→
   459→- `prompt` is non-empty and at least 20 characters.
   460→- `explanation` is non-empty and at least 40 characters.
   461→- For MCQ types: at least 3 options, exactly one correct (for `single_mcq`) or at least two correct (for `multi_mcq` / `sentence_equivalence`).
   462→- Options have no duplicate text.
   463→- Distractors are not trivially wrong (e.g. "All of the above" with no other correct option, or "None of the above" as the only correct option — both flagged).
   464→- For writing/speaking: `model_answer` meets the minimum word/character count for the type.
   465→- For `quantitative_comparison`: `quantity_a` and `quantity_b` are both present and not identical strings.
   466→- For `reorder_paragraphs`: at least 3 items.
   467→- For `matching_pairs`: at least 3 pairs.
   468→
   469→### 9.2 Content quality checks
   470→
   471→- **Readability:** the prompt's Flesch-Kincaid grade is within ±2 of the target CEFR for the exam (configured in `exam_types.target_cefr`). Out-of-range prompts warn (do not block).
   472→- **Grammar:** the prompt is run through a grammar checker (LanguageTool CLI). Errors block submission; warnings (passive voice, long sentences) do not.
   473→- **Spelling:** the prompt is spell-checked against the platform dictionary (en-US by default; en-GB for IELTS UKVI). Misspellings block.
   474→- **Answer-key validation:** for objective types, the correct answer is re-derived from the explanation by a regex/keyword matcher (e.g. the explanation must contain the correct option's text). Mismatches block.
   475→- **Plausibility of distractors:** each distractor must share at least one keyword with the correct option OR the passage (so distractors are not obviously wrong). Distractors that share zero keywords with the source material are flagged.
   476→- **Time realism:** `time_seconds` is within the configured range for the question type (e.g. 30–180s for IELTS Reading MCQ). Out-of-range values warn.
   477→
   478→### 9.3 Bias and sensitivity checks
   479→
   480→- A sensitivity lexicon (slurs, stereotypes, sensitive historical references) is run against every question, explanation, and option. Hits block submission and notify the compliance admin.
   481→- A name-balance check warns if all names in a question set are from a single demographic (the platform's name pool is balanced across regions and genders).
   482→
   483→### 9.4 Difficulty calibration
   484→
   485→- For objective types, after 100 student attempts, the platform computes the actual difficulty (fraction correct) and compares it to the declared `difficulty`. Misalignment > 0.25 (e.g. declared `easy` but actual < 0.4 correct) flags the question for recalibration.
   486→- Recalibration is a non-breaking edit — only `difficulty` changes; no version bump.
   487→

   490→## 10. Duplicate Detection
   491→
   492→`QuestionBankService::duplicateCheck()` runs on every draft save and on every import row. It compares the new question against the entire bank using three signals:
   493→
   494→1. **Exact text hash.** `sha1(prompt_normalized)` where `prompt_normalized` is the prompt lowercased, with whitespace collapsed and punctuation removed. An exact hash match blocks submission.
   495→2. **Fuzzy text similarity.** A trigram Jaccard similarity ≥ 0.85 against any existing prompt blocks submission. A similarity between 0.70 and 0.85 warns and requires the reviewer to confirm.
   496→3. **Answer-key hash.** `sha1(correct_answer_normalized)` for objective types. A match against a different prompt blocks submission (the same answer under a different question is suspicious).
   497→
   498→### 10.1 Cross-source duplicate check
   499→
   500→The check also compares against:
   501→
   502→- every **retired** question (to prevent re-adding a known-duplicate);
   503→- every **imported external corpus** flagged by admins (e.g. a corpus of known official exam items — used only to **prevent** accidental duplication, never to **add** official content);
   504→- every other question in the **same import batch** (to catch intra-batch duplicates).
   505→
   506→### 10.2 Resolution
   507→
   508→- A blocked duplicate must be re-authored. The author can request a "duplicate override" from the compliance admin, who reviews the case and either approves the override (with a written justification in `exam_audit_logs`) or rejects it.
   509→- A warning-level duplicate is forwarded to the reviewer with the similar question linked; the reviewer decides.

   513→## 11. Audit and Reporting
   514→
   515→### 11.1 Audit log
   516→
   517→Every question lifecycle event writes to `exam_audit_logs`:
   518→
   519→- `created` (with full question JSON)
   520→- `submitted_for_review` (author, reviewer assignment)
   521→- `approved` / `rejected` (reviewer, comment)
   522→- `published` / `unpublished` (admin, version number)
   523→- `edited` (diff between old and new JSON)
   524→- `retired` / `unretired` (admin, reason)
   525→- `duplicate_blocked` (with the matched question's code)
   526→- `quality_check_failed` (with the failing check name)
   527→- `originality_violation_reported` (compliance admin only)
   528→
   529→The audit log is read-only (no UPDATE or DELETE in the application layer; DB-level triggers prevent it).
   530→
   531→### 11.2 Reports
   532→
   533→Admin → Reports → Question Bank offers:
   534→
   535→- **Bank health** (count by state, count by difficulty, count by tag, count by exam type, count by reviewer, average time-to-publish).
   536→- **Originality report** (every question with `source = 'original'` and the originality confirmation chain).
   537→- **Difficulty calibration report** (declared vs. actual difficulty for items with ≥100 attempts).
   538→- **Stale content report** (published questions not edited in 12 months; flagged for refresh).
   539→- **Reviewer performance** (per reviewer: SLA adherence, reject rate, override rate).
   540→- **Export** of any report to CSV or PDF.
   541→
   542→### 11.3 Compliance sign-off
   543→
   544→Before each release, `scripts/generate_audit_reports.php` produces a **Question Bank Compliance PDF** in `storage/private/reports/audit/`. It lists:
   545→
   546→- the total bank size;
   547→- the count of original-confirmed items;
   548→- the count of licensed items (with license URLs);
   549→- any items flagged for originality review;
   550→- the reviewer and approver chain for every published item.
   551→
   552→The compliance admin signs this PDF before the release tag is pushed.

   556→## 12. Quick Reference — Author's Checklist
   557→
   558→Before clicking **Submit for review**, confirm:
   559→
   560→- [ ] The question is 100% original (or licensed with attribution). No official exam item, no copyrighted third-party content.
   561→- [ ] The `question_code` is unique and follows the convention `Q-<EXAM>-<SECTION>-<NNN>`.
   562→- [ ] The `prompt` is clear, self-contained, and free of grammar/spelling errors.
   563→- [ ] The `explanation` teaches the concept (not just "the answer is A").
   564→- [ ] For MCQ types: exactly one correct option (single) or at least two (multi), with plausible distractors.
   565→- [ ] For numeric types: the answer is verified manually and the tolerance is set.
   566→- [ ] For writing/speaking: the `model_answer` meets the word/character minimum.
   567→- [ ] The `difficulty` reflects the actual challenge, not the topic.
   568→- [ ] The `tags` include at least one skill tag and one cognitive tag.
   569→- [ ] The `time_seconds` is realistic.
   570→- [ ] The duplicate check passed (no warning or it has been justified).
   571→- [ ] The quality checks passed (no errors; warnings reviewed).
   572→- [ ] The wording uses "X-style practice" and does NOT claim official affiliation.
